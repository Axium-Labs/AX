# AX 0.3.7

- Add opt-in `ax crew worker worker.json`, executing distributed assignments
  through the existing ACP runtime in isolated per-attempt workspaces.
- Add the `collaboration` Tool for capability discovery, asynchronous delegation,
  result/error/Observation reads, Artifact exchange and Workflow State checkpoints.
- Support multiple AX instances per Host and concurrent executions per AX,
  with independent local models, capabilities, memory/configuration and permissions.
- Recover durable work using AXCrew ownership/incarnation/generation leases,
  stable child request IDs and explicit checkpoints; no permanent Coordinator
  Agent or direct high-frequency AX-to-AX communication is required.
- Preserve the existing Crew device bridge by accepting legacy cwd only when it
  resolves to a registered local project root. Ordinary AX startup and core
  Agent Loop/Subagent/Task/Session/Memory behavior remain unchanged.

Validation during development: workspace Rust tests, fmt and clippy passed;
clippy retains existing unrelated warnings. Real three-AX-process collaboration
and legacy Crew control process tests passed. Windows x64 release build passed;
no additional release-time tests were run.

The distributed process scenario uses logical Hosts on one Windows computer,
a fake model and explicit sandbox off. Physical multi-Host networking/TLS/GPU
isolation has not been validated. Execution is at least once; resources are
scheduling reservations. Requires AXCrew 0.3.3 for the distributed control plane.
See [setup and limits](../distributed-collaboration.md).
