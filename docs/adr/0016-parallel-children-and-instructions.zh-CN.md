# 0016. 并行子任务分发、结构化回执与可解析指令

[English](0016-parallel-children-and-instructions.md) | **简体中文**

状态：已接受；扩展 0005、0008、0011、0014、0015

<a id="context"></a>
## 背景

AX 已可向隔离子代理委派工作，但控制器每个模型轮次只推进一个任务，已有队列就绪集合从未使用。子代理返回 `{success, output}`，控制器必须重读子对话记录才能了解实际情况；恢复细节只能重跑子代理。没有确定性加载项目指令的方法，模型也无法提出会实质改变结果的问题，只能猜测，或结束轮次寄望下一条用户消息重新开启工作。

本次变更由四个目标驱动：任务成功率、总完成时间、工具与模型调用效率，以及长任务稳定性。

<a id="decision"></a>
## 决策

**指令通过解析获得，不通过召回。**确定性解析器读取全局指令文件、仓库根 `AGENTS.md`、根到 cwd 每一级目录的 `AGENTS.md`（同级 `AGENTS.override.md` 替代它），以及 `path`/glob 作用域匹配任务提及文件的 `.ax/rules/*.md`。每段带 `source_path`、作用域、优先级和来源，最具体层级优先。不经过记忆、嵌入或语义索引。项目指令有独立上下文槽，不属于记忆、技能或系统上下文。

**运行时接纳整个就绪前沿。**所有依赖为 `Completed` 时，`pending` 变为 `ready`。全部就绪且无冲突任务在 supervisor 并发上限内一批分发到现有 `AgentSupervisor`，其他任务完成时接纳新就绪任务；控制器不会等一个子任务结束才启动下一个。冲突由现有资源模型决定：任务可声明 `resources`（路径或名称，含写入标记），声明访问重叠的任务绝不并行。失败或超时子任务记录回执，前沿继续推进。

**子代理返回回执，而不是一句话。**`ChildResult` 包含 id、任务 id、状态、摘要、发现、变更文件、diff 统计、诊断、验证、产物、失败原因、续接提示及指标（墙钟时间、模型轮次、工具调用、报告 Token、失败工具调用）。模型只看到 `model_summary()`，完整记录持久化；`child_result` 控制工具按 id 读取完整记录、诊断、产物、diff、验证或指标，无需重跑。

**询问用户会挂起执行。**`request_user_input` 是用于询问用户偏好的正式结构化控制工具，绝不用于询问运行许可。提问会为 Goal、队列、Session 和问题保存检查点，将队列挂起为 `waiting_for_user` 后返回；答案写回同一工具调用 id，从该位置继续，不新增用户轮次。

**边界不变。**内核仍负责权限、沙盒、资源冲突、依赖、超时／预算和取消，模型仍决定搜索、读取、委派、修改及下一步尝试。不增加进度门槛、恢复锁、固定搜索顺序或规划不变量。主代理与子代理共用一个 `ToolRegistry`；差别仅为上下文、cwd、记忆作用域、沙盒边界和任务输入。

**轮次超时是空闲超时。**合法委派的轮次覆盖整个子任务批次，每个子任务有独立预算；只有整个窗口内毫无进展才取消控制器。模型轮次、工具轮次、子任务分发或回执均算进展。

<a id="consequences"></a>
## 影响

独立工作重叠执行，不再每模型轮次串行一个任务，从而缩短完成时间；回执投影使控制器上下文保持较小。失败局限于任务、恢复会话不重跑已完成子任务、挂起不视为失败，提高稳定性。

接受的代价：

- 并发子任务同时配置工作区，磁盘和 `SQLite` 竞争随并发增加。因此子任务分发、配置和清理共用每个子根目录的准入锁，配额统计容忍正在退出的目录，不使无关子任务失败。
- 控制器轮次超时不再按墙钟限制整个委派批次，改由各子任务预算限制，超时在此才有意义。
- `task_queue` 新增 `resources` 字段，`GoalTurn` 新增 `Answer` 变体；均为增量变更，旧检查点仍可加载。
- 子代理和 child host 实现 `ChildCheckpoint::finish(&mut ChildResult)`，不再接收 `ChildOutcome`，使 host 可补充只有它知道的事实，如权威 `git` diff。
