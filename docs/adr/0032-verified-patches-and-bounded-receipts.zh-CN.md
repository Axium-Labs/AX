# 0032. 经验证的补丁与有界回执

[English](0032-verified-patches-and-bounded-receipts.md) | **简体中文**

状态：已接受

<a id="context"></a>
## 背景

仅行坐标无法检测过时替换。补丁确认未显示最终本地上下文，相同发现响应在模型上下文重复完整正文，保留回执存储没有字节上限。原始历史必须保持权威，操作限制应明确指定或由 ContextBudget 派生。

<a id="decision"></a>
## 决策

凡 `delete_count > 0` 必须提供 `expected_lines`，写入前验证所有 hunk，缺少预期内容视为无效输入。成功回执包含逐字变更区域、最终行号及两侧最多两行上下文。各 hunk 遵循其原区域末行行尾，插入遵循前一行行尾。EOF 插入先为未终止前行补行终止符，再插文本；其他未编辑字节不变。

同轮相同发现响应只含指向首次调用的简短 `reused_from` 引用，不重复正文或诊断数组。状态和截断标记保留；类型化同轮结果依赖沿引用获取原回执。首次响应及原始历史保留证据。

全部输出缓存写入，包括恢复的旧条目，共用 FIFO 4 MiB `MAX_RETAINED_OUTPUT_BYTES` 上限，按 ID 和原始输出长度估算。独立缓存限制避免回执保留耦合到文件读取策略；原始字节估算避免每次缓存操作分配序列化副本。淘汰最旧条目，单份超限回执不缓存。未知或已淘汰 ID 明确要求重读文件或重跑原工具，不新增无界淘汰墓碑或启动工作。

<a id="consequences"></a>
## 影响

旧调用方替换／删除时也必须提供预期内容。补丁输出支持立即检查，不证明语法或构建正确。模型只看到一份发现正文，依赖的类型化调用仍获得原值。恢复后回执可用性也有限；持久历史保持无损，独立于便利缓存。命名保留上限提供确定性负载界限，不引入 core 到 tool 的依赖。
