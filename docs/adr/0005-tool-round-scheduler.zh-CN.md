# 0005. 识别依赖关系的工具轮次调度

[English](0005-tool-round-scheduler.md) | **简体中文**

状态：已接受

<a id="context"></a>
## 背景

顺序执行会让独立模型工具调用彼此等待。根据工具名、审批级别或提示措辞决定并发，无法安全识别共享文件系统、Git、数据库和 Memory 的影响。同名调用并发时，生命周期事件也需要真实调用 ID。

<a id="decision"></a>
## 决策

工具通过 `Tool::resources` 声明资源读写访问。未知影响使用全局独占租约，权限保持为独立契约。运行时根据类型化结果引用、显式依赖元数据及资源冲突构建 DAG，默认最多运行四个就绪 future，提供有界可配置上限；冲突副作用保持确定顺序，除非数据依赖要求反向排序。

路径资源规范化且具有层级关系，Memory 锁定实际数据库文件。Shell/Git 和未分类外部工具保持保守。资源租约在进程内跨内核共享，取消时释放；交互审批独立串行处理。

结果保留原工具调用 ID。原始检查点按完成顺序保存，下一模型请求按调用顺序接收已完成轮次。类型化结果引用和依赖元数据属于运行时工具 schema，其 schema 开销计入 `ContextBudget`。

<a id="consequences"></a>
## 影响

独立异步工作可重叠，无需无限制创建任务。生产者失败会阻止依赖副作用，无关调用仍可继续。环和无效 ID 在执行前失败，现有中断恢复仍生成格式正确的历史。

工具作者必须准确声明影响才能获得并发；未声明工具以并行度换安全。锁仅协调同一进程内 AX 调用，不协调外部进程或独立 AX 可执行程序。任务内异步调度器不会让同步 CPU 工作并行。
