# ADR 0030：统一的模型自主委派

[English](0030-unified-model-selected-delegation.md) | **简体中文**

状态：已接受，2026-10-20。

<a id="context"></a>
## 背景

普通子代理与队列子任务采用不同并发额度。队列子任务不继承普通绝对深度预算，深度 0 并非统一本地委派开关。类型化读取清单自动选择子执行，但数据映射不代表委派决策。指引也需覆盖编程以外工作。

<a id="decision"></a>
## 决策

保留单一执行循环，由主模型判断任务拆分。通用策略鼓励在聚焦上下文、独立核对或并行推进足以抵偿协调开销时进行有界委派，覆盖研究、写作、文档审查、分析、规划和编码。不要求拆分、固定角色名、复杂度分类器或额外规划请求。用户指定顺序、范围、授权及独立工作要求仍为权威。

两条本地委派路径共用既有并发池和绝对深度／配置，默认 8 / 1。槽位覆盖配置直至结算，等待祖先占用槽位；嵌套准入耗尽时本地拒绝，避免等待已占槽祖先。普通子代理保留 64 次准入的有限保护，队列批量大小独立于并发度。兼容 `with_child_concurrency` setter 写同一上限。

共用子绑定继承权限上限、允许工具、有效配置、深度加一及池，再将 host 重绑定到子工作区。运行时在队列准入和分发时检查禁用、深度与工具边界，恢复工作也不例外。子代理不能调用控制器队列控制。禁用的恢复队列保留任务标识、子句柄和回执，返回控制器执行，向模型提供本地反馈。提示指引或工具可用性不推导权限授权。

新类型化清单默认由控制器执行。显式 `task_queue action=configure` 可改变执行模式，不替换任务标识、进度、依赖或回执。追加记录仅在当前运行时限制允许时保留已有显式 children 选择。有界每轮可用性上下文暴露有效限制，不发模型／网络请求，也不创建子代理。

<a id="consequences"></a>
## 影响

队列并发默认从独立的 4 改为 8。深度 0 禁用全部新本地子执行，包括恢复队列。深度和继承工具允许时，队列子任务可普通嵌套委派。读取后模型显式选择可能需要一次配置调用，防止数据观测静默选择执行策略。模型仍可能做无益拆分；运行时限制约束资源／权限影响，不证明拆分改善质量。
