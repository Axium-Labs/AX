## 核心设计决策

### 1. 写入顺序：JSONL 优先

```rust
// 1. 追加到 JSONL（原子操作）
let (offset, length) = append_event(&self.events_dir, &stored)?;

// 2. 更新 SQLite 索引
transaction.execute(
    "UPDATE messages SET event_offset=?2, event_length=?3 WHERE id=?1",
    params![id, offset, length]
)?;

// 3. 提交事务
transaction.commit()?;
```

**理由**：
- JSONL 是真相之源（Source of Truth）
- 索引可以重建，事件不可丢失
- 崩溃后自动恢复

### 2. 恢复机制：自动且幂等

`sync_session_locked()` 在每次读写前执行：

```rust
// 快速路径：一切同步
if legacy_count == 0 && file_size == indexed_end {
    return Ok(());
}

// 慢路径：扫描 JSONL，重建索引
// 迁移旧的 SQLite 消息
```

**理由**：
- 无需手动修复
- 支持增量迁移
- 崩溃安全

### 3. Agent State 单独存储

```rust
if kind == MessageKind::AgentState {
    transaction.execute(
        "INSERT INTO agent_states(...) VALUES (...)",
        params![id, session_id, content, metadata, created_at]
    )?;
}
```

**理由**：
- Agent State 跨压缩保留
- 快速读取（无需扫描 JSONL）
- 独立的查询路径

### 4. 压缩不删除原始事件

```rust
// 只更新水位线
transaction.execute(
    "INSERT INTO session_summaries (...) VALUES (...)
     ON CONFLICT(session_id) DO UPDATE SET
     through_message_id = MAX(session_summaries.through_message_id, excluded.through_message_id), ...",
    params![session_id, summary, compressed_message_count, through]
)?;
```

**理由**：
- 完整的审计轨迹
- 支持历史查询
- 可以重新压缩

## 性能特性

### 写入性能

- **JSONL 追加**：O(1)，文件末尾追加
- **SQLite 索引**：O(log N)，B-Tree 插入
- **整体**：约 1-2ms/消息（包括 fsync）

### 读取性能

- **分页查询**：O(log N + K)，索引查找 + K 条记录
- **JSONL 随机读**：O(1)，直接 seek 到偏移量
- **内存占用**：只加载请求的消息，不加载全部历史

### 存储开销

- **典型会话**（100 条消息）：
  - 迁移前：50 KB（纯 SQLite）
  - 迁移后：55 KB（10 KB 索引 + 45 KB JSONL）
  - **+10% 开销**

- **收益**：
  - 完整的审计轨迹（JSONL）
  - 崩溃安全的写入（只追加）
  - 独立的备份（可单独复制 JSONL）
  - 更快的查询（更小的 SQLite）

## 崩溃恢复场景

| 崩溃时机 | JSONL 状态 | SQLite 状态 | 恢复结果 |
|---------|-----------|------------|---------|
| 追加 JSONL 前 | 无变化 | 无变化 | 消息丢失（预期，事务未提交） |
| `fsync` 后，索引前 | 完整事件 | 索引缺失 | ✅ `sync_session_locked` 重建索引 |
| 索引后，提交前 | 完整事件 | 事务回滚 | ✅ 下次写入时重新索引（幂等） |
| 提交后 | 完整事件 | 索引完整 | ✅ 一切正常 |

## 关键代码示例

### 写入新消息

```rust
pub fn append_message(&mut self, session_id: &str, message: NewMessage) -> Result<StoredMessage> {
    let transaction = self.connection.transaction_with_behavior(TransactionBehavior::Immediate)?;
    
    // 1. 恢复检查
    sync_session_locked(&transaction, &self.events_dir, session_id)?;
    
    // 2. 创建索引占位符
    transaction.execute("INSERT INTO messages (...) VALUES (...)", ...)?;
    let id = transaction.last_insert_rowid();
    
    // 3. 构造完整消息
    let stored = StoredMessage { id, session_id, role, kind, content, metadata, created_at };
    
    // 4. 追加到 JSONL
    let (offset, length) = append_event(&self.events_dir, &stored)?;
    
    // 5. 更新索引
    transaction.execute("UPDATE messages SET event_offset=?2, event_length=?3 WHERE id=?1", ...)?;
    
    // 6. Agent State（如需要）
    if kind == MessageKind::AgentState {
        transaction.execute("INSERT INTO agent_states(...) VALUES (...)", ...)?;
    }
    
    // 7. 提交
    transaction.commit()?;
    Ok(stored)
}
```
